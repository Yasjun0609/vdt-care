# VDT Care

한국어 | [English](./README.md)

> 화면을 무의식적으로 대하는 방식에서 감지되는, 아직 인지하지 못한
> 시력 문제에 대한 조기 신호 — 진단이 아니며, 안과 검진을 대체하지 않습니다.

---

## 개요

VDT Care는 캘리포니아의 한 안경원에서 일하며 관찰한 실제 문제에서
출발한 컴퓨터 비전 프로젝트입니다.

이 프로젝트는 좁은 질문 하나를 다룹니다: **웹캠으로 무의식적인
보상 행동(화면 쪽으로 기울이기, 가까이 다가가기)을 감지해서, 본인이
아직 인지하지 못한 시력 검사의 필요성을 신호로 보여줄 수 있는가?**

VDT Care는 시력 문제를 진단하거나, 렌즈 도수를 추정하거나, 안과
전문의를 대체하지 않습니다. 오직 행동 신호를 감지해서 사용자에게
시력 검사를 고려해보라고 제안할 뿐입니다.

---

## 배경

안경원에서 일하면서, 컴퓨터 화면을 또렷하게 보는 데 어려움을 겪는
환자들을 자주 만났습니다. 많은 분들이 노안이나 예전 처방을 그대로
쓰고 있었고, 아직 검진을 받으러 오지 않은 상태였습니다 — 본인의
시력이 변했다는 걸 꼭 알고 있는 건 아니었습니다.

제가 주목한 건 단순히 그분들이 눈을 찌푸린다는 것이 아니었습니다.
많은 분들이 자신이 그러고 있다는 걸 인지하지 못한 채, 모니터 쪽으로
몸을 기울이거나 고개를 가까이 가져갔습니다. 행동이 인지보다 먼저
나타난 거죠.

이 프로젝트는 바로 그 간극 — **무의식적인 신체 반응과 본인의 인지
사이의 간극**을 감지하려는 시도입니다.

---

## 문제 정의

기존 접근성 도구(폰트 크기 조절, 확대/축소, OS 접근성 설정)는 모두
사용자가 이미 그게 필요하다는 걸 인지하고 있어야 작동합니다.

하지만 많은 사람들은 스스로 그 인지에 도달하지 못합니다. "안경이
필요할지도 모른다", "처방이 바뀌었을지도 모른다"는 생각으로
이어지기 훨씬 전부터, 몸으로 먼저 적응합니다 — 기울이고, 가까이
다가가면서요.

VDT Care는 바로 이 지점을 겨냥합니다: 사용자가 알아채고 행동하기를
기다리는 대신, **무의식적인 보상 행동 자체를 조기 신호로 감지**하는 것.

### 타겟 사용자

다음에 해당하는 컴퓨터 사용자 (주로 40대 이상):
- 노안이 있거나 처방이 예전 그대로일 가능성이 있음
- 아직 시력 검사를 받으러 가지 않음
- 본인이 인지하지 못한 채 화면 쪽으로 기울이거나 가까이 다가감

## 멘토 피드백과 방향 전환

초기 아이디어는 감지된 피로도에 따라 텍스트를 자동으로 확대하거나
대비를 조정하는, 적응형 UI 도구에 가까웠습니다.

멘토(AI 엔지니어)가 프로젝트 방향을 바꾼 질문을 던졌습니다:

> "여기서 왜 컴퓨터 비전이 필요한가요? 그냥 폰트 크기를 키우라고
> 하거나 기존 OS 접근성 설정을 쓰라고 하면 안 되나요?"

이 질문으로, 원래 아이디어는 사실 CV가 꼭 필요하지 않다는 게
드러났습니다 — "글씨를 크게 만드는 것"은 기존 도구로 이미 해결되는
문제였으니까요. 프로젝트는 **적응형 UI**에서 **행동 신호 감지**로
방향을 전환했습니다: CV는 제품 자체가 아니라, 달리 관찰할 방법이
없는 문제(사용자 본인이 문제를 인지하지 못함)를 감지하는 수단입니다.

두 번째 피드백("10의 리소스로 풀 수 있는 문제를 100, 50, 20을 써서
푸는 건 비효율적이다 — 단순히 테크스택을 보여주려는 게 아니라면")을
계기로 범위를 한 번 더 정리했습니다 — 아래 **고려했다가 뺀 것들**
참고.

전체 기록: [`/mentor_feedbacks`](./mentor_feedbacks),
[`/dev_blogs`](./dev_blogs)

## 고려했다가 뺀 것들

이 프로젝트가 스코프에 정직하고, 오버킬로 가지 않도록:

| 고려했던 것 | 뺀 이유 |
|---|---|
| 자세(posture) 모니터링 | 성격이 다른 문제(인체공학)이며, 별도의 감지 파이프라인이 필요함. 시력 필요성 신호와는 무관 |
| 눈 찌푸림 감지 | 별도의 CV 접근이 필요함. 이미 검증된 단일 신호(지속적인 근접/기울임)만으로도 권고를 정당화하기에 충분했음 |
| 텍스트/대비/줌 자동 조정 | 기존 OS 접근성 도구가 이미 해결하고 있는 문제 — CV가 풀어야 할 차별화된 문제가 아님 |
| 분석 대시보드 | 핵심 가설 검증에 불필요함. 신호는 늘지 않으면서 표면적만 늘어남 |
| FastAPI 백엔드 + Streamlit 대시보드 | 서버 사이드가 필요한 지점을 아직 찾지 못함. 클라이언트 사이드만으로 충분하고 더 단순함 |
| 렌즈 도수 추정 / 자가진단 | 설계상 명확히 범위 밖 — 이 프로젝트는 진단 도구가 아님 |

더 자세한 내용: [`/interview_notes`](./interview_notes)

## MVP 범위

**포함:**
- 웹캠 권한 + 얼굴 인식 (MediaPipe FaceLandmarker)
- 얼굴-카메라 거리 추정 (눈 랜드마크 간 픽셀 거리)
- *지속적/반복적* 근접·기울임 감지 (일시적 움직임 제외)
- 부드러운 추천 UI (예: "시력 검사를 받아보는 걸 고려해보세요")

**명시적으로 제외 (v1):**
- 계정, 로그인, 클라우드 저장, 데이터베이스
- 챗봇 / 대화형 인터페이스
- 자세 교정 또는 인체공학 코칭
- 눈 운동
- 렌즈 처방 추정
- 어떤 형태든 자가진단

---

## 작동 방식

1. **얼굴 인식** — MediaPipe FaceLandmarker로 웹캠 프레임 처리
2. **거리 프록시** — 눈 코너 랜드마크 간 픽셀 거리를, 절대값이 아닌
   상대적 근접도 지표로 사용
3. **패턴 감지** — 세션 동안 *지속적인* 근접/기울임만 신호로 판단하고,
   짧고 일반적인 고개 움직임은 걸러냄
4. **추천** — 진단이 아닌, 자극적이지 않은 단일 제안(시력 검사 고려)

**오늘 시간 대비 진행률이 예상보다 느렸던 이유**: 이 항목의 세션
예상치는 원래 1세션이었는데, 실제로도 1세션 안에 끝나긴 했지만
시간의 상당 부분이 코드 자체보다 **환경 문제 디버깅**에 들어갔어요:
- npm 미설치 문제
- 파일 구조(`src/`) 재배치 문제
- Chrome 하드웨어 가속 비활성화로 인한 WebGL 실패
- Firefox 카메라 접근 실패

즉, 오늘의 +15%는 "코드 작성"보다 "코드+환경 문제 해결"을 합친
결과예요. 이런 디버깅 시간은 다음 리포트 세션 추정에서도 계속
변수로 남아있어요 (아래 "이 추정이 흔들릴 수 있는 변수" 참고).

## 시간/일정 추정

- **남은 세션 수**: 약 4.5~5개
- **세션당 소요 시간**: 1~2시간 (지금까지 페이스 기준)
- **주당 세션 빈도**: 1~2회 (지금까지 페이스 기준)
- **총 남은 작업 시간**: 대략 6~9시간
- **예상 전체 완료일**: 약 2~3주 후 → **2026년 8월 초~중순**
- **배포(라이브 URL)까지만 볼 때**: 최종 문서 정리 전 단계라 조금 더 빠름 → 약 2~2.5주 후, **2026년 8월 초**

## 이 추정이 흔들릴 수 있는 변수

- 오늘 같은 환경 이슈(하드웨어 가속, npm 미설치 등)가 또 나올 수 있음 — 세션 하나를 통째로 먹을 수 있음
- 임계값 튜닝은 "실제로 앉아서 써보며 조정"하는 작업이라 정확한 시간 예측이 어려움 — 1세션에 안 끝나면 +1세션 추가될 수 있음
- 그래서 위 추정은 **낙관적인 하한선**에 가깝고, 여유를 두면 3~4주(8월 중순)까지도 정상 범위

## 왜 이 정도로 짧게 잡을 수 있는지

스코프를 계속 좁게 유지했기 때문이에요. 오늘까지 나온 "오버킬 방지" 결정들(자세 모니터링·눈 찌푸림·대시보드·백엔드 안 넣기)이 없었다면, 이 추정은 최소 2~3배는 늘어났을 거예요.

# 072126 & 072226 - 스파이크를 React로 포팅하고, 환경이랑 씨름한 하루

## 오늘의 목표
HTML 스파이크에서 이미 검증된 거리 감지 로직을, 진짜 React +
TypeScript 훅(`useFaceDistance`)으로 포팅하고, 실제 프로젝트 안에서도
동일하게 동작하는지 확인하는 것. 딱 이것만.

## 뭘 했나
- Vite + React + TS 프로젝트 스캐폴딩 (package.json, tsconfig,
  vite.config, index.html)
- `useFaceDistance.ts` 작성 — 스파이크의 카메라 + MediaPipe
  FaceLandmarker 로직을 정식 훅으로 포팅. 버릴 코드였던 스파이크에는
  필요 없었던 두 가지를 추가함: 언마운트 시 정리(카메라 스트림 중지,
  애니메이션 프레임 취소), 그리고 이 훅은 오직 거리 신호만 책임지고
  "가까운지 판단"은 하지 않도록 분리(그건 다음 세션의 레이어)
- 최소한의 `App.tsx`를 테스트 화면으로 작성 — 최종 UI 아니고, 훅이
  잘 작동하는지 눈으로 확인하기 위한 용도임을 명시

## 뭐가 안 됐나
- Node는 깔려있는데 npm이 따로 안 깔려있었음 (`node -v`는 되는데
  `npm`은 안 됨) — 배포판에서 패키지가 분리돼있던 것, `apt install
  npm`으로 해결
- 파일을 `src/` 폴더 없이 리포 루트에 평평하게 붙여넣어서, Vite가
  `/src/main.tsx`를 못 찾음 — 폴더 구조 정리해서 해결
- Chrome에서 MediaPipe가 WebGL 컨텍스트 에러로 실패함
  (`emscripten_webgl_create_context() returned error 0`) — 알고보니
  Chrome 자체 설정에서 하드웨어 가속이 완전히 꺼져있었음
  (`chrome://gpu`로 확인: WebGL, Compositing, Rasterization 전부
  "Disabled" 또는 "Software only")
- 1차 조치로 MediaPipe 델리게이트를 GPU에서 CPU로 바꿨는데, 도움은
  됐지만 그것만으론 부족했음 — Chrome 설정에서 하드웨어 가속을 다시
  켜고 브라우저를 재시작할 때까지 텍스처 바인딩 에러가 계속 남음
- Firefox는 별개로 카메라 접근 자체가 안 됐음 — 아마 이전 테스트에서
  Chrome이 카메라 장치를 계속 붙잡고 있었던 것으로 보임

## 결과
Chrome에서 하드웨어 가속을 켜고 재시작한 뒤, 정상 작동함: 눈 랜드마크
2개 추적, 실시간 거리 값(166.8px), 기준 대비 98%로 "tracking" 상태
표시 — 스파이크 때와 완전히 동일한 동작. 작동하는 모습을 휴대폰으로
짧게 영상도 남겨둠 (데모 증거용).

## 오늘 굳이 안 파고든 결정 하나
하드웨어 가속이 꺼진 사용자는 똑같은 오류를 겪을 것. 이걸 위한
fallback UX는 오늘 일부러 설계 안 함 — 지금 사용자는 정확히 1명(나)
뿐이고, MVP 자체가 완성되지도, 다른 사람이 써보지도 않은 상태에서
fallback부터 만드는 건 아직 확인 안 된 문제를 미리 푸는 것. 할 일이
아니라 향후 고려사항으로만 여기 남겨둠.

## 타임라인 점검
남은 MVP 작업(지속 패턴 감지, 추천 UI, 임계값 튜닝, 가벼운 비주얼
다듬기, Vercel 배포)을 대략 추정해봄. 지금 페이스면 세션 4~5개,
대략 2~3주 정도. 스코프를 계속 좁게 유지한 덕분에 이 추정이 이 정도로
짧게 나온 것.

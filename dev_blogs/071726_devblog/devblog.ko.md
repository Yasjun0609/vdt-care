# 071726 - README 재작성과 "오버킬" 대화

## 배경
포맷/번역 확인하려고 예전 README.md를 올렸는데, 마지막 업데이트가
6/9였다는 걸 발견함 — 멘토 피드백(6/13)보다 4일 전. 여전히 피벗
이전 버전을 그대로 담고 있었음: 텍스트/대비 자동 조정, 자세
모니터링, FastAPI + Streamlit, 분석 대시보드, 훨씬 넓은 타겟 유저
목록. 지금 프로젝트가 실제로 서있는 지점이랑 하나도 안 맞았음.

## 중간에 나온 얘기
README를 손대기 전에, 예전 버전이 왜 저렇게 됐는지 솔직하게
얘기하게 됨 — 내 안에 이 프로젝트를 구직용 쇼케이스로 만들고
싶은 마음이 있다는 거, 문제를 풀고 싶은 것만큼이나 테크스택을
최대한 쌓아 보여주고 싶은 마음("요즘 다들 AI 쓰는데 안 쓰면
도태될까봐")이 있다는 거.

Claude랑 이걸 풀어봤음. 도움이 됐던 리프레임: 멘토의 "오버킬"
피드백은 "쇼오프하지 마라"가 아니라 "네가 두 개의 목표(문제 해결
vs 역량 과시)를 자각 없이 하나의 프로젝트에 섞고 있다"는 지적이었음.
여기서 MediaPipe/CV를 쓰는 건 정당함 — 문제 해결에 실제로 필요한
메커니즘이니까. 근데 자세 모니터링, 대시보드, FastAPI/Streamlit은
*이* 문제에는 필요 없음. 테크스택 범위를 보여주고 싶으면 그건 다른
작은 프로젝트들의 몫이지, 이 프로젝트의 몫이 아님.

## 뭘 했나
- 예전 README를 지우지 않고 아카이브함
  (docs/archive/README_v1_pre-mentor-feedback_060926.md) — 가설 →
  피드백 → 피벗이라는 스토리를 말로 설명해야 하는 게 아니라 눈에
  보이는 증거로 남김
- README.md를 실제로 확정된 스코프로 재작성: 타겟 유저, 문제 정의,
  멘토 피드백 + 피벗, MVP 범위, 테크스택(React + TS + Vite +
  MediaPipe, 백엔드 없음)
- "고려했다가 뺀 것들" 섹션 추가 — 자세 모니터링, 눈 찌푸림 감지,
  UI 자동 조정, 대시보드, FastAPI/Streamlit 백엔드를 명시적으로
  나열하고 각각 뺀 이유를 적음
- README.ko.md로 한국어 번역본 작성, 영어 버전과 상호 링크
  (한국 취업시장도 타겟이므로)

## 결과 / 배운 것
"고려했다가 뺀 것들" 섹션이 생각보다 훨씬 값어치가 있었음 — 오버킬
대화 자체를 인터뷰에서 말로 설명해야 할 것에서, 이미 repo 안에
보이는 것으로 바꿔놓음. "X를 안 만들었다"를 "X를 고려했고, 이래서
뺐다"로 리프레임하니까 완전히 다르게 읽힘.
